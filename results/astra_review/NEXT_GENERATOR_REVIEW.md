# Next interface-generator review — 2026-10-22

**Conditional recommendation if v17 also lacks a credible native interface:** one official RFdiffusion target-conditioned backbone, then two predeclared ProteinMPNN sequences and the existing coordinate-free validation. Prefer this over immediately installing original BindCraft. This is a tiny feasibility/interface-acquisition pilot, not a production campaign or a hit-rate estimate. No software installation, deployment or GPU allocation was performed for this review.

## Why change generators

The current evidence separates foldability from binding: two earlier hard sequences predicted plausible monomers but failed native interface checks; v16's reduced-domain search also screen-failed and its saved pose has a broken peptide. Its selected hard sequence still requires v17's result before deciding the next branch. More confidence weights or seeds in that same setup would not test a sufficiently new explanation.

RFdiffusion conditions a backbone generator on target geometry and hotspot features. In the official source, hotspot-conditioned, non-scaffold runs select `Complex_base_ckpt.pt`; hotspot indicators enter model features. This is a substantive change from differentiating AF2 predictions through sequence logits. It is a reason to try the method, not proof it will bind this receptor. [Official model runner](https://github.com/RosettaCommons/RFdiffusion/blob/86507b6538f51fce57b5a72477165f03999ed7ae/rfdiffusion/inference/model_runners.py).

Original BindCraft is a valuable independent implementation control, with published experimental support, but still uses AF2 backpropagation followed by MPNN and structural filtering. Its source explicitly constructs a ColabDesign binder model and adjusts confidence/contact losses. It therefore changes implementation more than the core search mechanism. A failure or success would not, by itself, identify a BindCraft2 bug. [Official BindCraft implementation](https://github.com/martinpacesa/BindCraft/blob/7713aa0d0d351e4117a8befeb8541f3a8ebd3368/functions/colabdesign_utils.py), [primary BindCraft paper](https://www.nature.com/articles/s41586-025-09429-6).

## Integration blockers to resolve before allocation

**Runtime is not already available.** The official Dockerfile pins CUDA11.6.2, Python3.9, PyTorch1.12.1 and DGL1.0.2, plus SE3Transformer. That is a different stack from the working BindCraft2/JAX image. Reusing the working image or assuming H100 compatibility is unsupported. Prefer a separate official-derived, version-pinned image; record checkpoint hashes and effective configuration. The current source can silently choose CPU when CUDA is absent, so the supervised worker must reject that fallback. No H100/A100 memory or elapsed-time claim was measured here. [Official Dockerfile](https://github.com/RosettaCommons/RFdiffusion/blob/86507b6538f51fce57b5a72477165f03999ed7ae/docker/Dockerfile), [official inference entry point](https://github.com/RosettaCommons/RFdiffusion/blob/86507b6538f51fce57b5a72477165f03999ed7ae/scripts/run_inference.py).

**Do not trust an assumed chain layout.** Current `Sampler.sample_init` preserves fixed receptor chain/residue IDs and allocates a new chain for generated residues; `run_inference.py` writes its `chain_idx` and `idx_pdb`. However, `ContigMap.get_mappings` still exposes legacy `con_hal`/`receptor_con_hal` numbering. Those metadata fields must not blindly rename the actual PDB. Compare actual output records, native sequence and coordinates; use explicit tensor-index/input-reference mapping and verify author189–383 before passing the object to the existing restoration adapter. Plain `con_ref_pdb_idx` metadata describes inpainted fragments and can be empty in target-only generation; receptor/complex mappings are the relevant input identities. CPU-test this conversion with the exact pinned revision. [Official contig mapper](https://github.com/RosettaCommons/RFdiffusion/blob/86507b6538f51fce57b5a72477165f03999ed7ae/rfdiffusion/contigs.py).

**Hotspot and fixed-target checks must inspect actual features.** Verify all declared input hotspot identities survive mapping and become the intended model features; a syntactically accepted list is insufficient. Require target sequence/structure masks to remain fixed, no target inpainting and a finite native backbone. Geometry may be represented in a transformed frame, so restore by the existing all195-residue fit rather than assuming original coordinates. Check actual predicted target geometry before replacement; replacing a deformed target must not hide its error. [Official hotspot mapping helper](https://github.com/RosettaCommons/RFdiffusion/blob/86507b6538f51fce57b5a72477165f03999ed7ae/rfdiffusion/inference/utils.py).

**The backbone still needs sequence design.** RFdiffusion writes designed residues as glycine/backbone-only. The official workflow then uses ProteinMPNN and AF2 filtering, with optional FastRelax. Plain MPNN is supported, so avoid adding a new relaxation workflow in this first pilot. The published large campaigns used many backbones; one sample is a capability test. Its published AF2 filter also supplied an initial guess, whereas our coordinate-free validation is deliberately a different test. Do not transfer reported success rates or filtering guarantees to this smaller, differently validated protocol. [Official binder-design guidance](https://github.com/RosettaCommons/RFdiffusion#practical-considerations-for-binder-design).

## Context and interpretation

Retain the195-residue contiguous native preparation for this first method comparison; do not return to disconnected crops. Generation on that domain is a search approximation. Restore the complete native receptor and observed glycans before interpreting physical access, and validate against the separately reconstructed native target. The current complex validator remains monomer-target inference plus CPU dimer restoration, not dimer-aware prediction. No acceptance gates change.

This is a bundled method change—backbone generator plus sequence assignment—not a one-variable causal experiment. That is defensible for candidate discovery now. Keep target, hotspot definition, length and validation fixed to make the outcome interpretable. Original BindCraft remains a fallback if RFdiffusion proves operationally unavailable, not a parallel installation task or automatic successor. Its official instructions also describe substantial trajectory counts for difficult targets; a one-run fallback would likewise be exploratory. [Official BindCraft guidance](https://github.com/martinpacesa/BindCraft).
